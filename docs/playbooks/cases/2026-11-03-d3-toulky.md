## Inferences

I1 (from F2) — a new detector class, **D7 catch-all program**: program 104
`mujrozhlas` holds >10k episodes of many real shows. Every show inside it is
a candidate for "move episodes to their real program" (url path
`mujrozhlas.cz/<show-slug>/…` identifies the show). This likely explains
a large part of D3 (targets with 0 episodes) and of D1.

I2 (from F3) — every station page with `b-004` cards is invisible to the
station crawl. Must measure how many of the D3 rozhlas.cz targets use b-004
(or other layouts) before changing code. Fix = parser accepts b-004 cards
(date absent → published_at None; duration from the badge).

I3 (from F4) — `fetch_archive_stubs` stops at the first fully-known page
assuming newest-first. On an oldest-first archive the second crawl would stop
at page 0 and never see new episodes. Also `max_pages=60` < 122 pages.
Fix = detect ordering (compare episode numbers / dates of page 0 vs last
page) and walk from the newest end; raise the page cap for the first walk.

I4 (from F1) — the paired mujrozhlas yt-dlp probe times out on very large
shows (180 s). For AUTO targets the rAPI path (index-only, fast) should be
used for the paired show instead of a full yt-dlp probe.

I5 (from F1) — a crawl that returns 0 every day is not reported anywhere.
MONITOR step: target with N consecutive empty crawls → flag on /system.
